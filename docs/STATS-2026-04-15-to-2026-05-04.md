### Recommended Immediate Actions

4. **Reduce Deepgram timeout** - Change from 600ms → 400ms (save 200ms on 81% of sessions)
5. **Improve merge prompt** - Add anti-leakage and anti-hallucination rules

See quality analysis document for detailed recommendations and testing protocol.

## 12. Root Cause Analysis: Regressions

### Regression 1: Deepgram Reliability (23% fallback rate)

**Baseline:** 3.8% single-source fallback (3 of 79 sessions)  
**Current:** 23% single-source fallback (23 of 100 sessions)

**Possible causes:**
1. Network/API instability in Apr-May period
2. Deepgram service degradation
3. Longer recordings = more opportunity for WS drops
4. Configuration change (endpointing, model version)

**Recommendation:** 
- Check Deepgram service status for Apr-May
- Review WS keepalive/timeout settings
- Consider adding WS reconnection logic for long recordings

### Regression 2: Deterministic Gating Effectiveness (5% vs 15%)

**Baseline:** 12 of 79 sessions (15%) skipped LLM via deterministic gating  
**Current:** 5 of 100 sessions (5%) skipped LLM

**Possible causes:**
1. Longer recordings = more complex transcripts = less exact agreement
2. Deepgram failures (23 sessions) automatically skip gating
3. Gating thresholds too conservative for longer content

**Recommendation:**
- Analyze gating near-misses (sessions that almost qualified)
- Consider length-adjusted thresholds
- Add similarity-score fast-path for long transcripts

### Regression 3: Deepgram Stop Reason (89% timeout)

**Baseline:** 80% finalize_timeout, 19% finalize_transcript  
**Current:** 89% finalize_timeout, 9% finalize_transcript

**Possible cause:** Longer recordings = VAD less likely to detect clean speech boundaries

**Recommendation:** Test `endpointing=150` (vs current 300) for faster speech-final detection

## 16. Conclusion

**Overall verdict:** The system is **significantly faster** (16-30% improvement across all normalized metrics) due to successful parallelization. However, **Deepgram reliability has regressed** (23% fallback rate vs 3.8% baseline), and **deterministic gating effectiveness has dropped** (5% vs 15%).

**Priority actions:**
1. Investigate and fix Deepgram reliability issues
2. Improve deterministic gating for longer transcripts
3. Tune Deepgram endpointing for cleaner speech detection

**What's working well:**
- Parallelization eliminated Deepgram from critical path in 70% of sessions
- Compression strategy (opus vs raw) is optimal
- Fallback resilience maintains 100% output delivery
- System handles longer recordings more efficiently
